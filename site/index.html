Windows + Linux · agentless · MIT

Deploy, patch and inventory your fleet from one executable.

PSCCM is a single Rust executable that deploys software and runs changes on Windows over WinRM and Linux over SSH, without installing an agent. Think PDQ Deploy, with a web console and a CLI.

PowerShell · admin box
# start the web console on http://127.0.0.1:8080/
psccm serve

# deploy to a group, one computer at a time
psccm deploy 7zip --group "Web farm" --batch-size 1

# ad-hoc command on several computers
psccm run web01,lb01 -s "Get-Service W3SVC"

# what's installed, and which updates are missing
psccm inventory software --name "Chrome*"
psccm updates list --security

Why not Ansible?

Runs on the admin box you already have.

The Ansible control node does not run on Windows (WSL only) and needs Python. PSCCM is one .exe that uses the remoting stack built into Windows.

01

One executable

Console, CLI, scheduler and package engine in a single Rust binary. Run it with the Windows installer as a service, portable from a folder, or under systemd on Linux.

02

Agentless by default

Targets need nothing beyond WinRM or SSH. Windows deployments can use the service account's Kerberos ticket, so there is no stored password.

03

Console and CI in one

Use the web console for everyday work. psccm deploy and psccm run wait for the result, print every computer's log and exit with 1 on any failure, so they slot into CI/CD pipelines.

Features

Everything a small IT team deploys, patches and tracks.

Built for mixed Windows and Linux fleets, from a handful of servers to every PC in the domain.

Agentless WinRM & SSH deploys

Windows over WinRM (PowerShell remoting, Kerberos/NTLM, encrypted). Linux over SSH with a password or key and sudo. Watch a live log for each computer.

  • Parallel computers, rolling batches, stop after N failures
  • One-off start times or daily / weekly / monthly / interval schedules
  • Redeploy to failed, with logs and a package snapshot kept per deployment

Active Directory import, read-only

Only LDAP searches for computer objects. No code path writes to AD, so the account needs no delegated rights.

  • ADSI with the console's own Kerberos ticket, or LDAPS / StartTLS
  • Tag by OU, skip disabled or stale computers, auto-sync
  • Imports add and refresh computers; they never delete any

Static & dynamic computer groups

Fixed lists, or rules re-evaluated every time a group is used, so new computers from AD join automatically. The editor previews matches as you type.

  • OS, name pattern, OU, OS version, AD security group, tag
  • Installed software with a version condition (<130)
  • Reboot pending, low disk space, Windows updates missing

Inventory & software report

Agentless, read-only scans of OS, hardware, disks, logged-on user, pending reboot and installed software, including Store / MSIX apps.

  • Software report across all computers, with CSV export
  • Outdated tab: one-click update from the App catalog
  • Change history (installed / removed / updated); uninstall from the report

Windows Update & Patch Tuesday

Asks each computer's own Windows Update Agent what is missing, from WSUS or Windows Update, and installs it as SYSTEM with automatic restarts.

  • Fleet-wide view of missing updates by KB and severity
  • Decline problem KBs so they are never installed
  • Monthly schedules: 2nd Tuesday + 2 days at 02:00 by default, in batches

GPO import & injection

Read GPOs from AD/SYSVOL (read-only) or a GPO backup folder, and apply their computer settings directly on chosen computers, with no GPO link and no AD change.

  • Registry policies, security settings and advanced audit policy
  • Re-apply on a schedule to fix drift; mode=remove to undo registry values

AD backup & restore

Scheduled backups of users, groups, computers, OUs and memberships, of every GPO and of DC System State. Compare a backup with AD and restore exactly what changed.

  • Recycle Bin restores, attribute-by-attribute reverts, GPO restore with links
  • Disaster recovery: rebuild the domain on a new server, under the same or a new name
  • Every restore is reviewed item by item, then confirmed by typing the domain name

Optional outbound-only agent

For computers with no WinRM or SSH. The same executable runs as a small service that connects out to the console, so nothing is opened inbound.

  • Live CPU, memory and disk analytics; on-demand event logs
  • Task Scheduler, firewall rules, local users & groups
  • In-browser terminal as SYSTEM, the logged-on user or another account

YAML packages

Plain YAML with detection, variables, conditions, retries, verify and rollback. Edit in the console, which validates before saving, or in any editor.

  • Rolling batches for HA pairs and web farms
  • Steps delegated to another host, e.g. drain HAProxy while patching IIS
  • Secret variables masked in logs and the UI

App catalog

Common Windows apps at their latest version, downloaded once to the console and pushed to targets, so they need no internet access.

  • Checked against the vendor's published SHA-256 where there is one
  • Daily check for new versions; optional auto-deploy to groups
  • Add your own apps in catalog.yaml

Microsoft 365, Teams & MSIX

Office through the Office Deployment Tool, the new Teams through Microsoft's bootstrapper, and any .msix / .appx provisioned for all users.

  • Install Office from the Microsoft CDN or a local share
  • Store apps appear in inventory and can be uninstalled from it

Web console + CLI

A web console for everyday use and a CLI for scripts and pipelines, covering deploys, ad-hoc commands, groups, inventory, updates, AD sync, GPOs and the catalog.

Installer & signed auto-update

An Inno Setup installer runs PSCCM as a Windows service. Updates come from GitHub releases and install only when the release is ed25519-signed with the PSCCM release key, never while a deployment is running.

Packages

Zero-downtime web farm releases in plain YAML.

The built-in iis-rolling-deploy package drains each IIS server on HAProxy, deploys the site, checks health and puts it back in rotation.

  • Delegated stepsdelegate_to runs a step on another computer: the HAProxy host over SSH, while the package itself targets Windows servers over WinRM.
  • Rolling batchesDeploy with batch size 1 and stop after failures 0, so only one server is out at a time and a broken build stops the rollout.
  • Reusable stepsinclude runs another package's steps; here the regular iis-site-deploy.
  • Detect, verify, rollbackAny package can skip computers that already have it, verify the result and roll back on failure, with retries and when conditions per step.
packages/iis-rolling-deploy.yaml · excerptFull file
id: iis-rolling-deploy
name: IIS - zero-downtime deploy behind HAProxy
category: IIS
platforms: [windows]
variables:
  haproxy_host:
    required: true
  backend:
    required: true
  server_name:
    default: "{{host_short}}"
  socket:
    default: /run/haproxy/admin.sock
  # … site, app_pool, package, health_url
steps:
  - name: Drain {{host_short}} on HAProxy
    delegate_to: "{{haproxy_host}}"
    os: linux
    script: |
      srv='{{server_name}}'
      out=$(echo "set server {{backend}}/$srv state drain" | socat stdio unix-connect:'{{socket}}')
      [ -z "$out" ] || { echo "$out"; exit 1; }
      # … wait until active sessions reach 0
  - name: Deploy site
    include: iis-site-deploy
  - name: Health check
    script: |
      # … Invoke-WebRequest '{{health_url}}', up to 12 attempts
  - name: Put {{host_short}} back into rotation
    delegate_to: "{{haproxy_host}}"
    os: linux
    script: |
      srv='{{server_name}}'
      out=$(echo "set server {{backend}}/$srv state ready" | socat stdio unix-connect:'{{socket}}')
      [ -z "$out" ] || { echo "$out"; exit 1; }

How it works

The console reaches out. Agents call home.

PSCCM connects to targets with the remoting already built into the OS. Computers that cannot be reached inbound run the optional agent, which connects out to the console instead.

Windows targets

Enable WinRM once, best by GPO (or Enable-PSRemoting -Force) and allow TCP 5985, or 5986 for HTTPS, from the console. Use FQDNs so Kerberos works.

Linux targets

SSH reachable, a user with sudo, plus bash and curl or wget. Host keys are pinned on first connect.

No remoting?

Run the one-line installer from Settings → Agents as administrator, or from a GPO startup script. The agent enrolls and appears under Agents.

Install

Up and running in minutes.

Download from GitHub Releases. Every release is signed and carries a build-provenance attestation.

Recommended

Windows setup

  1. Download and run psccm-setup-<version>.exe.
  2. Pick the port (default 8080) and network access: this computer only, or other computers too, with a generated access token.
  3. Set the service account: a domain account that is local admin on your targets (e.g. CORP\svc-psccm) gives Kerberos with no stored password.

Files go to C:\Program Files\PSCCM, data to C:\ProgramData\PSCCM. Upgrades keep the account and settings.

No install

Portable

  1. Download psccm-x86_64-windows.exe (or cargo build --release).
  2. Put it in a folder and double-click it.
  3. The console opens at http://127.0.0.1:8080/; data lives in data\ next to the executable.
# or expose it to other computers
psccm serve --bind 0.0.0.0 --port 8080 --token "long-random-string"
Linux console

Linux + systemd

Download psccm-x86_64-linux and the psccm.service unit.

sudo install -m 755 psccm-x86_64-linux /usr/local/bin/psccm
sudo useradd --system --home /var/lib/psccm --create-home psccm
sudo cp psccm.service /etc/systemd/system/
sudo systemctl enable --now psccm

Linux targets work from either console; Windows targets need a Windows console.

  1. Add credentialsIn Settings → Credentials, unless the service account already has access. They are encrypted for the account that runs the service.
  2. Add computersType them in or Import from AD, then create groups for the sets you deploy to.
  3. DeployPick a package and groups, tags or computers, press Deploy and watch the live log.

Security

Careful by design.

Anyone who can use the console can run commands as admin on every managed computer, so PSCCM is built to keep that power contained.

  • Read-only Active DirectoryImports, backups and GPO import only search AD and read SYSVOL. The console never writes to AD; a restore runs as a job on a DC only after two confirmations, and stops unless that DC is in the confirmed domain.
  • Encrypted credentialsPasswords are encrypted with DPAPI and never returned by the API; secret variables are masked in the API and logs. On a Linux console, prefer SSH keys.
  • SSH host-key pinningHost keys are pinned on first use. A changed key fails the deployment until you forget it in Settings.
  • ed25519-signed releasesUpdates install only when SHA256SUMS is signed by the release key built into PSCCM and the download matches. Assets also carry a build-provenance attestation.
  • Locked-down consoleBinds to localhost unless a token of at least 16 characters is set. Cross-origin requests are refused, and responses carry a Content-Security-Policy.
  • Verified downloadsCatalog downloads are HTTPS-only, and every deployment checks the installer's SHA-256 on the target before installing.
